# 진단 모드 기획서

> 상태: 기획 (2026-10-16). 사용자: "여러개 겪은다음에 증상을 보고 어떤걸 해야할지 어떤 행동을 어디다가 해야할지 유저가 맞추게하면?", "틀리면 뼈 다부서지거나 목이 뽑혀버린다거나 (잔인하겐말고) 병맛으로", "스트리머들이 할수잇게".

## 1. 한 줄 요약

환자의 증상을 보고 **어떤 시술을 어디에** 할지 플레이어가 고른 뒤 기존 손맛으로 시술한다. 진단이 맞으면 시원하고, 틀리면 만화처럼 터진다.

- 지금: "각도 맞추기" 한 가지 실력 게임
- 진단 모드: "뭘 해야 하지?"(판단)와 "잘 해야 하지"(손맛) 두 단계. 시청자가 채팅으로 훈수 두기 좋다.

## 2. 진입 조건과 판 구성

- 타이틀에 네 번째 버튼 **"진단 진료"**를 둔다. 기존 목꺾기·목뽑기·허리펴기는 연습장으로 남는다.
- 잠금: 세 연습 모드를 한 판씩 끝내면 열린다("여러 개 겪은 다음에"). 튜닝 패널에 잠금 해제 스위치를 둔다(테스트·스트리머용).
- 한 판 = 환자 **3명**(`PER_DAY`와 같다). 통증 3번이나 구급차로 끝나는 규칙은 그대로 둔다.

## 3. 한 환자의 흐름

| 단계 | 화면 | 시간 |
|---|---|---|
| 1. 입장 | 진료 기록지(주 호소·나이·직업) + 환자 첫 대사 | 기록지를 탭해서 닫을 때까지 |
| 2. 문진 (선택) | 질문 칩 2개 중 하나를 골라 단서 하나를 더 얻는다 | 탭 한 번 |
| 3. 진단 | **시술 카드** 6장 중 하나 → **부위** 고르기 | 탭 두 번 |
| 4. 시술 | 고른 시술의 기존 조작과 판정을 그대로 쓴다 | 모드별 기존 시간 |
| 5. 결과 | 맞으면 기존 성공 연출, 틀리면 6절의 오답 연출 | |

- 진단 단계에는 시간 제한을 두지 않는다. 스트리머가 채팅을 읽고 고민하는 시간이 콘텐츠다.
- 부위를 고르면 그 시술의 목표가 정해진다. 예: 목꺾기 C5 오른쪽 → `S.target` 회전 방향과 마디.

## 4. 시술 카드 (출시 버전 6장)

| 카드 | 부위 선택 | 현재 상태 |
|---|---|---|
| 목꺾기 | 마디 C3–C7 × 좌/우 | 있음 |
| 목뽑기 | 없음 (장력·중심은 시술 중에 맞춤) | 있음 |
| 허리펴기 | 등 위쪽 / 등 가운데 / 허리 | 있음 (`back.html`, 별도 페이지) |
| 턱 맞추기 | 좌/우 | **새로 만듦** (머리 모델·입 벌림 키 재사용) |
| 어깨 끼우기 | 좌/우 | **새로 만듦** (누운 환자, 팔만 움직임) |
| 돌려보내기 | 없음 | **새로 만듦** (꾀병·병원 가야 할 환자) |

조합: 목꺾기 10 + 목뽑기 1 + 허리 3 + 턱 2 + 어깨 2 + 돌려보내기 1 = **정답 19가지**.

## 5. 증상 카드 (환자 = 외형 × 증상)

진단을 다양하게 하려고 **캐릭터(외형·말투)와 증상을 분리**한다. 지금 5명은 캐릭터로 두고, 증상 카드를 따로 만들어 매 판 섞는다. 같은 박대리라도 오늘은 목, 내일은 어깨로 온다.

```js
// src/patient/cases.js (예시)
{id: "neck-rot-r", answer: {proc: "crack", seg: 5, side: 1},
 cc: "고개를 오른쪽으로 돌리면 뚝 걸려요", xr: "rot",
 ask: {"어디가 아파요?": "목 오른쪽 아래요", "언제부터요?": "아침에 일어났더니"},
 decoy: "어깨도 좀 뻐근하긴 해요"}         // 헷갈리게 하는 한마디
```

출시 목표 증상 카드 약 15장. 단서 규칙:

| 정답 | 대표 단서 (차트·대사) | 헷갈리는 단서 |
|---|---|---|
| 목꺾기 | "돌리면 걸려요", 한쪽 방향만 막힘 → 방향·마디 힌트 | 어깨 결림 |
| 목뽑기 | "목이 눌린 느낌", "팔이 저려요", 일자목·디스크 | 목이 안 돌아감 |
| 허리펴기 | "앉아 있으면 허리가 찌릿", 구역 힌트(등 위·허리) | 골반 통증 |
| 턱 | "하품하다 입이 안 다물어져요" (대사가 발음이 샌다) | 목 통증 |
| 어깨 | "농구하다 팔이 빠졌어요", 팔이 축 늘어진 자세 | 목 결림 |
| 돌려보내기 | 가슴 통증·발열(→ "큰 병원 가세요"), 꾀병("회사 가기 싫어요") | 그럴듯한 목 통증 |

- 직업 차트와 대사로 추리하는 맛을 준다(배달 라이더 → 헬멧 → 목 압박 → 목뽑기).
- 처음 두 환자는 단서를 노골적으로, 마지막 환자는 헷갈리는 단서를 넣는다.
- **돌려보내기 정답**: 치료사가 "큰 병원 가세요" 하고 환자가 "아 그래요?" 하며 걸어 나간다. 점수 보너스. 의료 행위로 오인될 소지를 줄이는 장치도 된다.

## 6. 오답 연출 (잔인하지 않은 병맛)

원칙: 피·살 찢김 없이 **고무·장난감·만화 물리**로 터진다. 시술이 끝나면 환자는 멀쩡히 일어나 투덜대며 나간다(구급차 엔딩은 기존처럼 금·골절 세기에만).

| 정답 → 한 시술 | 연출 |
|---|---|
| 허리 환자 → 목꺾기 | 머리가 팽이처럼 세 바퀴 돌다가 반대 방향으로 멈춘다. 환자: "…허리 아프다고 했잖아요" |
| 목꺾기 환자 → 목뽑기 | 목이 엿가락처럼 늘어나 머리가 천장 형광등에 "띵" 부딪힌다 |
| 목 환자 → 허리펴기 | 환자가 침대째 트램펄린처럼 튀어 올라 천장에 박혔다가 떨어진다 |
| 아무나 → 턱 맞추기 | 턱이 서랍처럼 열렸다 닫히며 "딸깍딸깍". 대사가 한동안 웅얼거림 |
| 아무나 → 어깨 끼우기 | 팔이 프로펠러처럼 돌아 환자가 침대 위에서 반 바퀴 돈다 |
| 진짜 환자 → 돌려보내기 | 환자가 문 앞에서 고통에 몸을 꼬고 "…다시 올게요" (통증 1) |
| 같은 시술·틀린 부위 | 기존 실패 연출(뾰잉·뚜륵·손가락 뚝) + "거기 아닌데요?" |

- X-ray는 오답 연출 끝에 짧게 열어 **"정답은 여기였어요"**를 보여 준다(기존 `ring.js` 정답 표시 방식). 시청자가 "거봐 내가 뭐랬어" 하는 순간이다.
- 오답은 통증 1회. 판정 세기가 금·골절이면 기존처럼 구급차 엔딩.

## 7. 점수

- 진단 정답 +50, 부위 정답 +30, 이후 시술 점수는 기존 `scoreSuccess` 그대로.
- 문진 칩을 쓰지 않고 맞히면 "명의" 보너스 +20.
- 결과 화면: "진단 정확도 2/3", 오답 칩("팽이 ×1", "트램펄린 ×1").

## 8. 스트리머 요소

- 진단 단계에서 시간이 멈추고 카드가 크게 보여 화면 공유로 읽기 쉽다.
- 오답 연출은 4초 안에 끝나는 한 컷이라 클립으로 쓰기 좋다.
- 결과 화면의 **오늘의 사고 하이라이트**: 가장 웃긴 오답 장면 재생 + "구독자 훈수 정확도" 같은 문구 자리.
- 나중: 시청자 투표 연동(트위치 채팅)은 스팀판에서 검토한다.

## 9. 기술 구조

**가장 큰 문제: 허리펴기가 별도 페이지(`back.html`, `src/back/`)다.** 진단 모드는 한 판 안에서 목과 허리를 오가야 한다.

- 1단계: 목 계열(목꺾기·목뽑기·턱·어깨·돌려보내기)만 `index.html` 안에서 진단 모드로 만든다. 허리가 정답인 증상 카드는 넣지 않는다.
- 2단계: `src/back/`의 씬을 `index.html`에서 불러올 수 있게 모듈로 감싸고 모드 전환 시 씬을 교체한다(`towelStage.js`처럼 가시성·조명 복원).

새 파일:

| 파일 | 내용 |
|---|---|
| `src/patient/cases.js` | 증상 카드, `makeDiagDay(rand)` (캐릭터 × 증상 섞기) |
| `src/core/diagnosis.js` | 순수 함수: `judgeDiagnosis(answer, pick)` → correct / wrongSpot / wrongProc, 오답 연출 종류, 점수. 단위 테스트 대상 |
| `src/ui/diagPick.js` | 시술 카드·부위 선택 UI (공용 `clinic-hud.css`) |
| `src/game/diagFlow.js` | 진단 → 해당 시술 흐름으로 넘기기, 오답 연출 호출 |
| `src/scene/goofFx.js` | 팽이·엿가락·트램펄린·프로펠러 연출 (보이기만, 판정과 무관) |
| `src/scene/jaw.js`, `src/scene/shoulder.js` | 새 시술 2개 |

지켜야 할 것: 기존 판정·센서·카메라 규칙(AGENTS.md 3절)은 진단 모드에서도 그대로 쓴다. 진단은 시술 **앞**에 끼어드는 단계일 뿐이다.

## 10. 단계별 일정

| 단계 | 내용 | 결과물 |
|---|---|---|
| M1 | `cases.js` + `diagnosis.js` + 선택 UI, 목꺾기·목뽑기·돌려보내기만 | 판단 재미 검증 (증상 카드 8장) |
| M2 | 오답 연출 4종 (`goofFx.js`) | 스트리머 클립 소재 |
| M3 | 턱 맞추기 | 카드 5장 |
| M4 | 어깨 끼우기 | 카드 6장 |
| M5 | 허리 씬 통합 | 카드 전체, 정답 19가지 |
| M6 | 앱인토스 광고(구급차 이어하기) | 출시 |

M1만으로도 실기기에서 "고르는 게 재밌나"를 확인할 수 있다. 재미없으면 M2 이후를 다시 본다.

## 11. 정해야 할 것

1. 문진 칩(단서 하나 더)을 넣을지, 차트만으로 맞히게 할지.
2. 잠금 조건(세 모드 한 판씩)이 스트리머에게 진입 장벽이 되는지. 처음부터 열어 두는 안도 있다.
3. 돌려보내기의 "큰 병원 가세요" 카드가 앱인토스 심사에서 의료 조언으로 읽히지 않는지.
